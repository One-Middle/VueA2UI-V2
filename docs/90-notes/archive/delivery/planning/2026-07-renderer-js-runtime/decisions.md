# 决策记录

## 1. 使用 `action.script` 命名

`action.script` 比复用 `action.functionCall` 更明确。前者表达执行一段受限脚本，后者容易被理解为调用预注册函数。

## 2. 属性脚本只读

属性脚本用于渲染期计算，可能随着响应式更新反复执行。为避免渲染循环和隐式副作用，属性脚本只注入 `dataModel.get`。

## 3. `deps` 必填

属性脚本必须声明依赖路径。Renderer 通过 `deps` 建立最小订阅，保证 `dataModel` 变化后重新执行属性脚本。

## 4. 第一版只支持 `style.<白名单字段>.script`

第一版不支持 `style.script` 返回整个对象。样式脚本结果必须继续经过现有样式白名单，避免开放任意 CSS。

## 5. 第一版不做 Worker

MVP 使用主线程 SES。原因是当前脚本定位为可信简单逻辑，优先验证协议、能力注入和响应式链路。死循环和强超时留到后续 Worker + SES 阶段处理。

## 6. 动作能力使用分组注入

动作脚本中的额外行为通过能力分组注入，例如 `actions.emit(...)`。JSRuntime 不固定业务行为，只执行宿主提供的能力。
