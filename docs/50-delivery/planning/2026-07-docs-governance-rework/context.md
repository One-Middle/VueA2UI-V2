# 文档治理体系改造背景

## 1. 背景

当前 `docs/` 已有产品、架构、契约、模块、任务和归档分层，但仍存在几类问题：

- 文档目录没有显式区分权威文档、阅读笔记和历史归档。
- `tasks/current.md` 只能承载当前任务，不适合记录每次平台改造的计划、过程和结果。
- AI 生成的阅读材料缺少固定归宿，容易与权威文档混在一起。
- 模块文档偏重目录和职责，仍需强调关键类、核心对象和逻辑链路。

## 2. 目标

- 建立长期可维护的文档分层。
- 让每种事实有清晰的权威位置。
- 支持每次平台改造以独立计划目录沉淀。
- 兼容 AI 生成的非权威阅读笔记。
- 强化模块文档中的关键类和核心链路说明。

## 3. 非目标

- 不重写全部业务文档内容。
- 不把历史归档重新定义为当前契约。
- 不在本次改造中修复代码实现问题。
